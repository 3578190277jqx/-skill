# PPT 与口播稿

先读学校 PPT：页面比例、主题色、中文/西文字体、封面和正文版式、占位符、页脚页码与每页容量。简述实际提取结果，不假称见过未提供的模板。保持母版和占位符；具体文件操作优先使用环境内演示技能。不要把通用草稿导出器套上学校模板名称后声称精确复刻。

## 默认内容

没有另外规定时用 12–15 页。15 页示例安排：封面；背景与意义；国内外现状；目标与需求；业务流程；系统架构；模块设计；数据库概览；关键流程/时序；关键实现一；关键实现二；测试与结果；有依据的特色；不足与展望；致谢。12 页可合并相近内容，未有实现证据的页面改为待补信息，不生成虚假成果。

国内外现状和技术比较需要真实可查来源；材料不足时标出检索需求。创新点按“对比对象—具体差别—学生贡献—证据”说明；常规 CRUD、使用流行框架本身不自动算创新。

正文每页默认 3–5 个要点，每点不超过 20 个可见字符；封面、致谢、单图页可例外。细节放演讲备注。页面文字简练，口播自然，论文才使用完整学术书面语。避免“赋能、闭环、抓手、打通”等空词。

每页提供：标题、页面文字、图及来源、演讲备注、预计秒数、证据或待确认项。大纲阶段可写 `[图: 预约业务流程]`；最终成品应插入真实图像或明确交付为含缺口草稿。备注要写入 PPT 的演讲者备注区。

## 限时与精简路线

- 用户指定全篇 8 分钟，则各页分配合计 480 秒，封面和致谢通常更短，关键设计/实现/结果页更多。15 页平均约 32 秒，不能同时承诺逐页 60–90 秒。
- 未指定总时长，可按原工作流每页 60–90 秒写完整练习稿，并明示 12–15 页约需 12–22.5 分钟；若缺少现场限时，另问限时，不擅自把长稿称作短稿。
- 时间分配只是计划，按实际中文口播字数估算并进行试读核对；不能把 JSON 的 `seconds` 合计正确当作已验证口播时长。
- 最后给出 3 分钟路线：具体页码顺序、每页单独压缩后的口播及秒数，总计不超过 180 秒。不能只挑页码后继续照读长版备注。

## 验证

审查总页数、正文密度、主线及问答一致性；检查长稿和精简稿的实际内容。导出后重开检查页数、图像、主题与真实备注。能够渲染时逐页检查越界和缺字；工具无法渲染时说明边界。学校模板已有内容不要无条件删除；另存新文件并说明保留/替换方式。
